# Countdown на macOS и iOS

## Требования и первый запуск

- Mac с Xcode и установленными Command Line Tools.
- Flutter **3.44.0** (как в CI), CocoaPods.
- macOS **10.15+**, iOS **13+**. Для разработки требуется macOS, поддерживаемая выбранным Xcode и Flutter.

Из корня репозитория:

```bash
flutter config --no-enable-swift-package-manager
flutter pub get
flutter doctor -v
flutter run -d macos
```

Проекты Apple включены в репозиторий. Повторный `flutter create .` не нужен.
Используется CocoaPods, поскольку зависимости уведомлений требуют его интеграции.

Для iOS запусти Simulator из Xcode либо подключи iPhone:

```bash
open -a Simulator
flutter devices
flutter run -d <device_id>
```

## Сборка macOS

```bash
flutter build macos --release
open build/macos/Build/Products/Release
```

Приложение: `Countdown.app`. В GitHub Actions → **Apple builds** → успешный
запуск → **Artifacts** доступен архив `Countdown-macOS`.
Сборка CI не имеет Developer ID и notarization: это тестовый результат,
а для распространения без предупреждений Gatekeeper нужны подпись и notarization
через Apple Developer. Не отключай Gatekeeper глобально.

## Сборка iOS

Проверка компиляции для устройства без сертификатов:

```bash
flutter build ios --release --no-codesign
```

Для установки на свой iPhone открой `ios/Runner.xcworkspace`, выбери Runner →
Signing & Capabilities → свою Team, установи уникальный Bundle Identifier
(сейчас `com.countdown.countdown`) и запусти приложение на подключённом устройстве.
Вход в Apple ID и сертификаты настраиваются в Xcode, их не нужно добавлять в Git.

Для TestFlight / App Store нужна Apple Developer Team. После настройки подписи:

```bash
flutter build ipa --release
```

Архив из CI `Countdown-iOS-simulator` предназначен только для симулятора той же
архитектуры, что и runner CI, и не устанавливается на физический iPhone.
CI отдельно проверяет release-сборку для iPhone без подписи, но не выпускает IPA.

## Поведение на Apple

- При первом старте таймера приложение просит разрешение на уведомления.
  Если отказал, разреши их в системных настройках уведомлений для Countdown.
- На iOS и macOS завершение планируется через системный центр уведомлений,
  поэтому уведомление не зависит от выполнения Dart-кода в фоне или после выхода.
  Focus / «Не беспокоить» и системные настройки могут скрыть уведомление или звук.
- На macOS закрытие последнего окна завершает приложение. Запланированное
  уведомление сохраняется; при следующем запуске состояние и статистика восстанавливаются.
- «Не гасить экран» удерживает дисплей включённым только во время отсчёта,
  пока приложение работает. Ручной сон, блокировка и закрытая крышка не отменяются.
- Звук управляется настройкой приложения и системными разрешениями.
  У macOS нет вибромотора; вибрация iOS зависит от системных настроек.

## Проверка перед выпуском

1. Запустить короткий таймер с открытым приложением: одно уведомление и сохранённая статистика.
2. Повторить со свёрнутым приложением и после его закрытия; открыть снова, проверить состояние.
3. Сбросить таймер до конца: уведомление не должно прийти.
4. Проверить звук, отказ в разрешении и выключенные уведомления.
5. Проверить настройку удержания экрана, изменение размеров окна Mac и поворот iPhone/iPad.

Автоматически: `flutter analyze`, `flutter test`, workflow **Apple builds**.
Проверки на реальных устройствах, подпись и notarization выполняются отдельно.
